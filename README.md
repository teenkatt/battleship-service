# Battleship service

Игровой сервис для турнира по морскому бою. Контракт API — [CONTRACT.md](CONTRACT.md).

Реализованы все пять ручек контракта. Сервис ведёт несколько партий одновременно, состояние каждой
сессии живёт в PostgreSQL.

| Метод | Путь | Что делает |
| ----- | ----- | ----- |
| POST | `/game` | создаёт сессию и возвращает свою расстановку |
| POST | `/game/{session_id}/shot` | называет клетку, по которой стреляет |
| POST | `/game/{session_id}/shot/result` | принимает результат своего выстрела |
| POST | `/game/{session_id}/opponent-shot` | отвечает `miss` / `hit` / `killed` по своему полю |
| POST | `/game/{session_id}/close` | закрывает сессию; повторное закрытие — 400 |
| GET | `/ping` | проверка живости сервиса |

## Как поднять

1. `cp .env.example .env`
2. `docker compose up -d --build`

Сервис слушает порт 8000, миграции применяются при старте контейнера `api`.

## Как проверить

- тесты: `docker compose exec api pytest`
- документация API: http://localhost:8000/docs
- остановить: `docker compose down`

## Принятые решения

- **Тактика.** Сервис не повторяет свои выстрелы. Получив `hit`, он бьёт по соседним клеткам, а раненый
  корабль из двух и более палуб добивает с концов линии. После `killed` клетки вокруг потопленного корабля
  не обстреливаются: корабли не соприкасаются, там заведомо пусто. Остальные выстрелы идут по клеткам одной
  чётности — так быстрее находятся двухпалубные корабли. В среднем на весь флот уходит около 58 выстрелов.
- **Повторный выстрел противника** в ту же клетку ошибкой не считается: сервис снова честно отвечает по
  своему полю, поэтому по уже потопленному кораблю ответ остаётся `killed`.
- **Очерёдность.** Пока сервис ждёт результат своего выстрела, повторный `/shot` возвращает 409, а результат
  без сделанного выстрела — тоже 409.
- **Некорректный запрос** (неизвестная координата, неизвестное значение результата, отсутствующее поле)
  возвращает 400 и тело `{"detail": "..."}`, как требует контракт.
- **Закрытая сессия** больше не играет: `/shot`, `/shot/result` и `/opponent-shot` отвечают 410. Повторное
  закрытие — 400, как требует контракт, а не 410.
- **Параллельные партии.** Сессии независимы, а запросы одной партии выстраиваются в очередь: каждая
  изменяющая транзакция занимает строку своей игры (`SELECT ... FOR UPDATE`). Поэтому два одновременных
  `/shot` не займут один ход, два `/close` не закроют сессию дважды, а одновременные попадания по одному
  кораблю дают ровно один `killed`. Поиск по `game_id` покрыт индексами.
